# yaklass-solver

Помощник для проверочных работ ЯКласс: **сервер** (API решения, Telegram-бот, канал управления) и
**клиент** на ПК пользователя (куки и аккаунт остаются у него, запросы идут с его IP).

| Часть | Где | Статус |
|---|---|---|
| Сервер (`yaklass_server/`) | ваш сервер, за nginx, без Docker | готов, см. [docs/SERVER.md](docs/SERVER.md) |
| Протокол агент ↔ сервер | [docs/PROTOCOL.md](docs/PROTOCOL.md) | описан |
| **Руководство пользователя** | [docs/USER_GUIDE.md](docs/USER_GUIDE.md) | установка, сценарии (без сервера, чужой/свой сервер, консоль), решение проблем |
| Архитектура и принципы | [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) | описана |
| Консольный клиент (`yaklass_bot/`) | ПК | работает (`yaklass-bot`), ниже |
| GUI-приложение (`yaklass_app/`) | ПК, EXE/AppImage в Releases | готово, см. [docs/CLIENT.md](docs/CLIENT.md) |

Тесты: `pip install -e ".[server,gui,dev]" && pytest` (тесты по страницам ЯКласса требуют локальной папки
`samples/`, в репозиторий она не входит и пропускается автоматически).

# yaklass-bot

Помощник для проверочных работ ЯКласс. Кроссплатформенный (Python ≥ 3.11).

## Установка
Нужен Python ≥ 3.11 и [uv](https://docs.astral.sh/uv/) или [pipx](https://pipx.pypa.io/).

**Из папки проекта или готового wheel (`dist/*.whl`):**
```bash
sh install-cli.sh                                   # Linux / macOS
sh install-cli.sh yaklass_bot-0.1.0-py3-none-any.whl
```
```powershell
powershell -ExecutionPolicy Bypass -File install-cli.ps1   # Windows
```
Скрипт ставит команду `yaklass-bot` глобально (изолированное окружение), подтягивает Playwright
и скачивает Chromium. Вручную то же самое: `uv tool install "путь/к/проекту[browser]"` (или `pipx install ...`).

**Обновить после изменений в коде:** `uv build && uv tool install --force "dist/yaklass_bot-*.whl[browser]"`.
**Удалить:** `uv tool uninstall yaklass-bot`.

Установщик в конце сам запускает **стартовую настройку**; её же можно запустить в любой момент:
```bash
yaklass-bot setup      # или просто `yaklass-bot` при первом запуске
```
Мастер спрашивает: из какого браузера брать куки (и проверяет, что вход в ЯКласс виден), чем решать
(API: OpenAI / OpenRouter / Ollama / другой сервер, модель, vision, ключ — в переменной окружения или в файле
с правами только для вас), нужен ли SearXNG, и каким браузером
заполнять задания (встроенный Chromium или установленный Chrome/Edge). Настройки лежат в `config.toml`
(папка настроек ОС; `config.toml` в текущей папке имеет приоритет) и правятся вручную.
Если конфига нет, любая команда в терминале сама предложит настройку. Перед запуском войдите в ЯКласс
в выбранном браузере и закройте его (иначе файл кук может быть заблокирован).

## Команды
| Команда | Что делает |
|---|---|
| `yaklass-bot check` | один раз проверить «Новые работы» |
| `yaklass-bot watch` | проверять постоянно (интервал и джиттер в конфиге) |
| `yaklass-bot run [URL] --dry-run` | тестовый режим: открывает страницу в видимом браузере, выставляет ответы, **не отправляет** — «Ответить» жмёте вы; при переходе на следующее задание заполняет и его |
| `yaklass-bot solve-file page.html [--prompt-only] [--search]` | отладка: разобрать сохранённое задание и получить ответ LLM |

`-c путь/к/config.toml` указывается **перед** командой.

## LLM
Любой OpenAI-совместимый API: OpenAI, DeepSeek, OpenRouter, Ollama, LM Studio, vLLM... (`yaklass-bot setup`).
Ключ — в переменной окружения или в файле с правами только для вас.

## Тесты
`pytest` (используют сохранённые страницы из `samples/`).

## Режимы запуска (`run`)
```bash
yaklass-bot run [URL] --dry-run      # тест: заполнить ответы, НЕ отправлять (отправляете вы)
yaklass-bot run [URL] --auto         # автономно: решить, ОТПРАВИТЬ, завершить работу (необратимо!)
```
Без URL открывается список работ (одна новая работа — берётся сама, несколько — спросит номер).
Нужен Playwright и браузер: `pip install -e ".[browser]"` и `playwright install chromium`
(или `[run] channel = "chrome"` / `"msedge"` в config.toml).

**`--dry-run`.** На странице старта показывает условия (заданий, лимит времени, попытки) и сам жмёт «Начать»/
«Продолжить» через `--start-delay` секунд (5; Ctrl+C — отмена; `--no-start` — не жать). Дальше выставляет ответы,
но «Ответить» не трогает. Безопаснее начинать с тренировочных заданий (`/p/...`).

**`--auto`.** Перед стартом просит подтверждение (`--yes` — без вопроса). Затем:
1. «Начать» / «Продолжить»;
2. задания **с первого по последнее**: решает, заполняет, проверяет, что поля встали, и жмёт «Ответить»;
   если задание уже выполнено (кнопка «Сохранить») — **перезаписывает ответ** и сохраняет; если ответ не
   изменился, «Сохранить» неактивна и бот ничего не делает;
3. на «Список заданий» жмёт «Завершить» (форма завершения есть, только когда ответы даны на все задания).
Если какое-то задание не удалось (нет ответа модели, поле не заполнилось, аудио), работа **не завершается**:
окно остаётся открытым, чтобы вы доделали вручную (`--finish-anyway` — попытаться завершить всё равно,
непроверено). `--resume` после сбоя пропускает задания, уже отправленные ботом в этой попытке
(учёт в `tasks.csv` рядом с `works.csv`). Бот перестаёт решать, когда до конца таймера < 45 с.
Шаг завершения написан по сэмплам страницы, на живом сайте не проверялся.

## Поиск (SearXNG)
Если в `config.toml` указан `[search] searxng_url`, по умолчанию (`mode = "always"`) перед **каждым** ответом:
1. модель формулирует 1–2 поисковых запроса (при сбое — запрос строится из условия);
2. запросы уходят в SearXNG, из первых страниц берутся абзацы, больше всего похожие на условие;
3. всё это идёт модели как справочные материалы (помеченные как данные, а не инструкции), а ответ включает
   `evidence` — цитату-основание, которая печатается в консоли для быстрой проверки.
Поиск не зависит от «желания» модели искать. `mode = "model"` — модель просит поиск сама (`{"search": "..."}`,
подходит сильным моделям), `mode = "off"` — без поиска. Для `solve-file` есть `--no-search`.
В SearXNG должен быть включён формат json (`search: formats: [html, json]` в settings.yml), иначе будет 403.
Страницы читаются только по публичным адресам (во внутреннюю сеть скрипт не ходит).

## Локальная модель (Ollama)
`yaklass-bot setup` -> API -> Ollama. Для работы в режиме JSON включается `json_mode`. Учтите: у Ollama по умолчанию
короткий контекст (часто 2–4 тыс. токенов), результаты поиска могут не поместиться — увеличьте его
(`OLLAMA_CONTEXT_LENGTH=8192` или `PARAMETER num_ctx 8192` в Modelfile). Для заданий с рисунками нужна vision-модель.
