# Архитектура yaklass-solver

```
 Telegram ──► Бот ─┐                          ┌── ПК пользователя ──────────────────────┐
                   ├─ сервер (этот репозиторий)│  Агент (GUI-приложение, позже в Releases)│
  nginx ─► API ────┘   • /v1/link  привязка   │  • читает куки из СВОЕГО браузера        │
   (HTTPS, домен)      • /v1/solve  решение ◄──┼──• парсит страницы ЯКласса               │
                       • /v1/agent  WebSocket ◄┼──► • подставляет ответы, жмёт кнопки      │
                       • общий API модели      │  • ходит на ЯКласс с IP пользователя      │
                       • SearXNG (опц.)        └──────────────────────────────────────────┘
```

## Принципы
1. **Куки, пароль и аккаунт ЯКласса остаются на ПК пользователя** и на сервер не передаются. Сервер видит
   только Telegram id, хеш токена агента, счётчик запросов и тексты заданий, присланные на решение
   (по умолчанию они не логируются: `LOG_TASKS=false`).
2. **IP пользователя**: все запросы к ЯКласс выполняет агент, а не сервер.
3. **Протокол управления узкий**: сервер может только попросить агента выполнить команду из белого списка
   (`status`, `list_works`, `start_work <число>`, `pause`, `resume`, `stop`). Ни адресов, ни кода, ни файлов.
   Взлом сервера не даёт исполнения кода на ПК пользователей.
4. **Токен агента** выдаётся по одноразовому коду из `/link` (10 минут), в БД лежит только SHA-256 хеш.

## Два режима «решателя» в клиенте
| Режим | Кто вызывает модель | Ключ | Лимиты |
|---|---|---|---|
| **Сервер** (по умолчанию) | сервер, общий API | у администратора | суточная квота, rate limit |
| **Свой API** | **само приложение на ПК** напрямую | у пользователя, хранится только локально | без лимитов сервера |

«Свой API» **не** проходит через сервер намеренно: иначе ключ пользователя пришлось бы хранить на сервере,
а сервер получил бы возможность ходить на произвольные адреса из настроек клиента (SSRF), и локальные
модели в домашней сети были бы недоступны. Сервер при этом нужен и в этом режиме — для Telegram-управления
(привязка, команды, уведомления); `/v1/solve` просто не вызывается.

## Хранилище
SQLite (один файл, стандартная библиотека Python, отдельный сервис не нужен). CSV не подходит из-за
нескольких процессов (сервер, `yaklassctl`), атомарных операций (одноразовые коды, счётчики квот) и
поиска токена на каждый запрос.
