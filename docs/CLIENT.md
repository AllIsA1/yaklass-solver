# Клиент: приложение Yaklass Solver

Приложение работает **на вашем компьютере**: вход в ЯКласс, куки и все запросы к сайту остаются у вас,
сервер видит только тексты заданий (для решения) и служебные события. Управление — из окна приложения
или из Telegram-бота.

## Установка
Скачайте из **Releases**: `YaklassSolver.exe` (Windows) или `YaklassSolver-x86_64.AppImage` (Linux:
`chmod +x … && ./YaklassSolver-x86_64.AppImage`). Если не подходит — Python-версия:
```bash
pip install "yaklass_bot-0.1.0-py3-none-any.whl[gui]"      # wheel из Releases
yaklass-app
```
Браузер для выполнения: на Windows по умолчанию Microsoft Edge (уже есть), на Linux — установленный Chrome,
иначе в «Настройки → Браузер → Скачать Chromium».

## Первый запуск
1. **Настройки → Сервер**: адрес, который дал администратор бота (`https://…`).
2. В Telegram боту `/link` → код → вкладка **Главная** → «Привязать».
3. **Главная → Войти в ЯКласс**: откроется окно браузера, войдите в аккаунт и закройте окно.
4. **Работы** → «Выполнить» (автономно) или «Только заполнить» (проверить и нажать «Ответить» самому).

## Что в настройках
- **Решатель:** *Сервер* (общий API, суточный лимит) или *Свой API* (OpenAI, DeepSeek, OpenRouter, Ollama…;
  запросы идут прямо с вашего ПК, ключ хранится в системном хранилище паролей или в файле с правами 600).
  Для своего API можно подключить SearXNG и выбрать режим поиска.
- **Темп работы:** пауза между заданиями, перед «Ответить», между полями, скорость набора. Сервер может
  задать минимальную паузу между заданиями.
- **Браузер:** собственный профиль приложения (рекомендуется) или куки вашего браузера; окно браузера — показывать/скрывать.
- **Приложение:** разрешить запуск работ из Telegram, как часто искать новые работы, тема.

## Как это работает
`Агент` держит WebSocket-соединение с сервером (исходящее, порты открывать не нужно), раз в N минут ищет новые
работы (headless-браузером) и сообщает о них в Telegram. Команды из бота (`list_works`, `start_work`, `pause`,
`resume`, `stop`, `status`) — единственное, что сервер может попросить; никакого кода и адресов (см. PROTOCOL.md).
Выполнение: «Начать/Продолжить» → задания с первого по последнее (уже выполненные перезаписываются кнопкой
«Сохранить») → «Завершить». Если хотя бы одно задание не удалось, работа **не завершается**, окно остаётся
открытым для ручного завершения. Лимит или недоступность сервера останавливают прогон.

## Сборка
```bash
pip install ".[gui]" pyinstaller
cd packaging && pyinstaller yaklass-app.spec --noconfirm --distpath ../dist-app --workpath ../build-app
# Windows (один .exe):  YK_ONEFILE=1 перед pyinstaller
# Linux AppImage:       bash packaging/build-appimage.sh      (из корня репозитория)
dist-app/YaklassSolver/YaklassSolver --selftest              # проверка сборки (QT_QPA_PLATFORM=offscreen)
```
Релизы собирает GitHub Actions по тегу `v*` (`.github/workflows/release.yml`): тесты → Windows .exe, Linux
AppImage, Python wheel → GitHub Release.

## Защита ЯКласса от автоматических запросов
Сайт стоит за защитой от ботов: обычный HTTP-запрос (без браузера) получает страницу-заглушку с JS-проверкой, а
**скрытый (headless) браузер может получить «403: Доступ запрещён — подозрительная активность»**, хотя в обычном
браузере с того же IP сайт открывается: вердикт зависит от признаков клиента, а не только от IP. Поэтому приложение:
- всегда использует настоящий браузер и **видимое окно** (вход, обновление списка работ, выполнение; параметр
  «Показывать окно браузера» лучше не отключать);
- по умолчанию **само не заходит на сайт**: список работ обновляется кнопкой «Обновить» и по команде `/works` из Telegram;
  автоматическая проверка включается галочкой в настройках (не чаще раза в 5 минут, по умолчанию раз в 60, ±20%,
  каждый раз открывает окно браузера на несколько секунд);
- распознаёт страницы отказа и «не робот», показывает причину, на 6 часов прекращает автоматические проверки
  и останавливает выполняемую работу.
Если отказ повторяется и в видимом окне — подождите и напишите в поддержку ЯКласса (info@yaklass.ru), указав дату,
IP и id со страницы ошибки.

**Вход в ЯКласс.** Куки входа сессионные: Chromium не сохраняет такие куки при закрытии браузера, поэтому приложение
хранит снимок кук профиля (`session-cookies.json`, права 600, в папке данных приложения) и возвращает их при следующем
запуске. Режим «куки браузера» читает куки из выбранного браузера (Firefox и др.) и передаёт их запущенному браузеру.

## Обновления
Приложение при запуске (через 20 с и далее раз в 12 часов) смотрит последний релиз в GitHub Releases. Если он новее,
на главной странице появляется плашка «Доступна новая версия» с описанием. Дальше два случая:
- **Windows `.exe` и Linux AppImage** — кнопка «Обновить сейчас». Приложение скачивает файл, проверяет его SHA-256
  (по цифре из ответа GitHub или из `SHA256SUMS.txt`), заменяет себя и перезапускается. AppImage подменяется атомарно;
  запущенный `.exe` Windows нельзя перезаписать, но можно переименовать: старый файл уходит в `*.old-…` и удаляется при
  следующем запуске. При несовпадении суммы, обрыве или нехватке прав файл удаляется, приложение остаётся прежним.
  Во время выполнения работы обновление отказывается.
- **Запуск из исходников/pip** — только ссылка на страницу релиза.
Ручная проверка: Настройки → Приложение; отключается галочкой «Узнавать о новых версиях при запуске».
**Приватный репозиторий:** GitHub отдаёт 404 без токена — проверка и скачивание заработают после открытия репозитория
(для проверки можно задать `YAKLASS_UPDATE_TOKEN`, он не сохраняется). Целостность обеспечивает HTTPS и контрольная сумма
из релиза; подписи релизов нет, поэтому доступ к GitHub-аккаунту владельца — критичная точка доверия.

## Известные ограничения
- Шаг завершения работы и поведение сайта после «Ответить» проверены на сохранённых страницах и фейковом
  сервере, на живом ЯКласс — только вручную пользователем.
- Первый запуск `.exe` может вызвать предупреждение SmartScreen (нет подписи кода).
- Нет значка в трее и автозапуска (в планах).
